# v1.3.2 改造清单（跨项目复用）

> 基于 `develop-1.3.2` 工作区未提交改动整理。目标：在另一套同构项目中按文件/模块逐项对齐，避免漏改。

## 总览

| 主题 | 要点 |
|---|---|
| 版本 | 全仓 `1.3.0` → `1.3.2`（`.env.example` / `pyproject.toml` / `frontend/package.json` / `src-tauri/Cargo.toml` / 各 `tauri*.conf.json` / `offline-bundle-manifest.example.json`） |
| 启动可靠性 | Tauri 后端解压进度事件、就绪缓存、资源诊断；首屏多路探活、更长等待（GPU 冷启动） |
| GPU 安装包 | NSIS 写权限/复制/解压校验；无旁路 zip 则中止安装；可选安装阶段解压后端 |
| 后端稳定性 | 任务进度 WS 节流广播；Bcut ASR 默认不走系统代理；Omni 多模态 PIL 放线程池 |
| 前端体验 | 加载页紧凑无滚动；Omni 管线 WS 进度；生产默认端口 `18000` |

## 2. Tauri 后端启动（`src-tauri/src/main.rs`）

### 2.1 状态与事件

- `AppState` 增加 `pending_backend_ready: Arc<Mutex<Option<BackendReadyPayload>>>`
- 新增 `BackendReadyPayload { port, boot_token }`
- `emit_backend_ready()`：写缓存 + `emit("backend-ready")`
- `backend_ready_status()`：统一返回就绪状态并触发事件

### 2.2 解压进度（Windows）

- 事件名：`backend-extract-progress`
- 载荷：`phase, extracted, total, current_file, current_index, total_files`
- `extract_backend_zip_with_progress()` 替代静默 `zip.extract()`；失败回退 PowerShell `Expand-Archive` 并 emit `fallback`

### 2.3 启动流程加固

- `BackendStartingLease`：`backend_starting` 任意返回路径自动复位（防卡死「正在启动中」）
- `backend_ready_wait_secs()`：dev `90s`，生产 `360s`
- `probe_backend_ready()` / `wait_for_backend_ready()` 分离；就绪判定以 HTTP `/api/hello` 为准
- 生产环境 zip 与解压目录均不存在 → 明确报错（提示旁路 `superAutoCutVideoBackend_gpu.zip`）
- 支持 `SACV_FORCE_BACKEND_REEXTRACT=1` 强制重解压
- 可执行文件候选增加嵌套路径 `superAutoCutVideoBackend/superAutoCutVideoBackend.exe`
- 失败时清零 `backend_port` / `backend_boot_token`

### 2.4 新 Tauri 命令（需注册到 `invoke_handler`）

| 命令 | 作用 |
|---|---|
| `take_pending_backend_ready` | 消费 Rust 缓存的就绪载荷（弥补前端 listen 晚于 emit） |
| `probe_backend_http_ready` | Rust 侧 HTTP 探活（端口缓存 + 18000/8000 + 扫描段） |
| `get_backend_resource_status` | 返回 zip/解压目录/exe 是否存在及 `ready` |

### 2.5 资源诊断

- `resolve_backend_resource_root()` / `inspect_backend_resource_status()` → `BackendResourceStatus`

### 2.6 其它

- `src-tauri/src/offline_bundle.rs`、`runtime_updater.rs`：仅格式/签名微调，逻辑不变

## 3. 前端启动与加载页

### 3.1 `frontend/src/services/clients.ts`

- `DEFAULT_PORT`：生产 `18000`，开发 `8000`（原固定 `8000`）
- `testConnection` 超时 `1s` → `3s`
- 新增类型：`BackendReadyPayload`、`BackendResourceStatus`
- `TauriCommands` 新增：`takePendingBackendReady`、`probeBackendHttpReady`、`getBackendResourceStatus`

### 3.2 `frontend/src/App.tsx`

| 项 | 改前 | 改后 |
|---|---|---|
| 总等待 | `180s` | `420s` |
| 探活 | 单次 `start_backend` + 超时 | 并行：`probeBackendReady()`（Rust 缓存/探活 + WebView 端口扫描 + `autoConfigureBackend`） |
| 轮询间隔 | 依赖单次 attempt | `800ms` 轮询直至就绪或超时 |
| 事件 | 无 | `listen("backend-extract-progress")` → 传给加载页 |
| 资源状态 | 无 | Tauri 下定时 `getBackendResourceStatus` |
| 防重入 | 无 | `startupInitStartedRef` 避免 StrictMode 双挂载重复初始化 |

核心函数（需整体移植）：

- `probeBackendByHello()`：多端口并行 `/api/hello` + handshake
- `probeBackendReady()`：多 probe Promise 竞速
- `withTimeoutOrNull()` 替代抛错式 `withTimeout`

### 3.3 `frontend/src/components/AppLoadingScreen.tsx`

- 导出 `BackendExtractProgress` 类型
- **布局**：`h-screen overflow-hidden`，内容区 `flex-1 min-h-0`，禁止整页滚动条
- **紧凑模式**：`elapsedSeconds >= 12` 隐藏部分装饰
- 展示：解压进度条、后端资源三态（zip / 解压目录 / exe）、杀软白名单提示精简
- 版本号移出滚动区，`shrink-0` 固定底部

### 3.4 `frontend/src/hooks/useProjects.ts`

- 新增 WS 监听：`scope === "omni_multimodal"` 的 `progress|completed|error|cancelled`
- 与现有 HTTP 轮询互补：收到 completed 拉取结果并刷新项目

### 3.5 小改

- `settingsPage/constants.ts`：「字幕识别」移至剪映路径后，标注「非必填」
- `OmniFullNarrationPipelineControls.tsx`：注释掉分步测试按钮区（保留全链路按钮）

## 4. 后端

### 4.1 `backend/modules/task_progress_store.py`

- `update()` 后按策略 **WebSocket 广播**（有活跃连接且存在 running loop）
- 节流环境变量（可选）：
  - `TASK_PROGRESS_WS_MIN_INTERVAL_SEC`（默认 `0.5`）
  - `TASK_PROGRESS_WS_KEEPALIVE_SEC`（默认 `2.0`）
  - `TASK_PROGRESS_WS_PROGRESS_DELTA`（默认 `0.25`）
- 终态（`completed/failed/error/cancelled`）立即推送
- `type` 由 `status` 推导（`_status_to_message_type`）

### 4.2 `backend/services/asr/asr_bcut.py`

- `_bcut_requests_session()`：`session.trust_env = False`（默认不走 VPN/系统代理）
- 环境变量 `BCUT_ASR_TRUST_ENV=1` 可恢复信任环境代理

### 4.3 `backend/services/omni_multimodal_pipeline_service.py`

- 同步封装：`_open_rgb_images_sync`、`_optimize_images_for_online_vision_sync`
- `Image.open` / `optimize_image_for_online_vision` 改为 `await asyncio.to_thread(...)`，避免阻塞事件循环

## 5. 打包脚本

### 5.1 `scripts/build.ps1`（GPU/安装器相关）

- `Repair-GpuNsisMultilineMessageBox`：修复 PowerShell here-string 把 NSIS `MessageBox` 拆成多行的问题（需 `$\r$\n`）
- `Patch-GpuNsisInstaller` 增强：
  - 安装前检测 `resources` 可写
  - 复制/重命名 zip 失败即 `Abort`
  - 校验 `resources\superAutoCutVideoBackend.zip` 存在
  - **无旁路 zip 且无已装 zip → 中止**（不再「仅装壳」）
  - 安装阶段用临时 ps1 + `Expand-Archive` 解压并校验 exe
- `-RuntimeChunks` 且未显式 `-EncryptPy` 时，GPU 变体 **默认开启** Cython 加密（`$doEncryptPy`）
- `InstallDir` / `APPNAME_DIR` 占位符调整（`${PLACEHOLDER_INSTALL_DIR}`）

### 5.2 新增脚本（整文件复制）

| 文件 | 用途 |
|---|---|
| `scripts/build-gpu-installer.ps1` | 薄封装：`build.ps1 -Variant gpu -SkipPortable` + 输出目录提示 |
| `scripts/collect-tauri-startup-diagnostics.ps1` | 收集安装目录日志/进程/端口探活 → `.sacv_diagnostics` 报告 |
| `scripts/dev-verify-backend-extract.ps1` | 开发：`FORCE_PACKAGED_BACKEND=1` + `cargo tauri dev` 验证解压进度 |

### 5.3 文档

- `docs/打包说明.md`：补充 NSIS 权限/解压校验说明；示例命令与版本号

## 9. 建议验证

1. **开发**：`.\scripts\dev-verify-backend-extract.ps1`，首屏应出现解压进度与资源状态。
2. **生产 GPU 安装**：无 `superAutoCutVideoBackend_gpu.zip` 同目录 → 安装器应报错退出。
3. **启动**：杀软/慢盘场景下 7 分钟内应就绪或出现「跳过等待」。
4. **Omni 多模态**：跑一条任务，前端进度应 WS 更新且完成后自动刷新结果。
5. **Bcut ASR**：开 VPN 时仍能连上（默认不走系统代理）。
