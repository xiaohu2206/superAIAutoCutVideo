# step4_9 分块精简设计

## 目标

由于大模型上下文有限，`step4_9` 不再一次性输入整份文案和全片镜头。  
改为：

- 文案分 chunk
- 每个 chunk 只输入对应的局部镜头范围
- 各 chunk 独立生成后再顺序拼接

---

## 核心原则

### 1. `matches[0]` 不能直接当真值
`matches[0]` 只能作为参考，不能直接决定 chunk 的镜头范围。  
原因是它可能受排序误差或全局路径影响，不一定准确。

### 2. 先给每条文案确定“局部候选区间”
对每条文案：

- 取 topK 候选镜头
- 以 `matches[0]` 作为参考中心
- 只保留时间上接近它的候选
- 用这些候选的最小 `start` 和最大 `end`，作为该文案的局部候选区间

这样做的目的，是避免单个候选错误把整条文案带偏。

### 3. 先按总文案数稳定切 chunk
文案先按顺序切 chunk，目标是**平均每组约 20 条**，但不要直接用 `round(N / 20)`。  
更稳妥的写法是：

- `chunk_count = max(1, ceil(N / 20))`
- `chunk_size = ceil(N / chunk_count)`


### 4. chunk 镜头范围只从本 chunk 的候选区间推导

先定义“单条文案的局部候选区间”。

对每条文案，不直接将 `matches[0]` 当作最终结果，而是按以下方式确定局部候选区间：

- 取 `matches[:10]` 作为候选池
- 对每个候选计算中心时间：`center = (start + end) / 2`
- 按 `center` 从小到大排序
- 将这些候选按时间分布聚成若干个 1 维小簇
- 对每个簇分别记录其区间值：`[min(start), max(end)]`
- 找到 `matches[0]` 所在的簇，将该簇对应的区间值作为当前文案的局部候选区间

补充说明：

- 设计层不写死固定秒数阈值，只要求先得到所有时间簇及其区间值
- `matches[0]` 只用于在这些簇中定位当前文案更可能落在哪个时间岛
- 若 `matches[0]` 恰好是离群点，则它通常只会落入一个很小的簇，不会把其他远处时间岛一并带入
- 若候选数不足 10，则按实际候选数处理

对一个 chunk：

- 收集其中所有文案的局部候选区间
- 取这些区间的总包络范围，得到 chunk 的镜头窗口
- 只保留该窗口内的镜头作为模型输入


## 最终流程

1. 统计文案总数 `N`
2. 用 `chunk_count = max(1, ceil(N / 20))` 和 `chunk_size = ceil(N / chunk_count)` 先顺序切好文案 chunk
3. 为每条文案生成局部候选区间
4. 为每个 chunk 生成局部镜头窗口
5. 每个 chunk 单独调用模型
6. 按原顺序拼接所有 chunk 的结果

---

## 一句话总结

第一版的关键不是找到“最优镜头”，而是：

**先按总文案数把文案稳定切成 chunk，再为每条文案收缩到可靠的局部时间区间，只把该 chunk 的局部镜头交给模型。**
