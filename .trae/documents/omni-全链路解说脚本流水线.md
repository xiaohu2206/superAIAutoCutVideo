# Omni 全链路解说脚本生成流程

> 产品视角说明：从「素材视频 + 解说文案」到「可以直接配音、合成视频、导入剪映的解说脚本」整条流水线，做了什么、产品边界在哪里。

## 1. 解决什么问题

把「一段素材视频 + 一段长文案」变成「文案句 + 镜头时间区间」的解说脚本。系统自动：

1. **理解素材**：把整段视频切成「会说话的语义段」，每段带字幕、画面理解和向量。
2. **理解文案**：把整段长文案切成结构化小段，每段带向量。
3. **匹配镜头**：为文案的每一句话挑出最贴合的镜头候选。
4. **生成脚本**：让大模型把「文案 + 候选镜头」改写成「解说句 + 起止时间」，写入 `project.script`，供配音、视频合成、剪映草稿使用。

整条流水线无人值守、可重试、可取消、可断点续跑，进度实时反馈到前端。

## 2. 全流程一览

```
用户上传：素材视频 + 解说文案

┌────────────────────────────────────────────────────────┐
│ 阶段 A：生成分镜                                          │
│   A0  必要时先同步把字幕提取出来                          │
│   A1  镜头切分 + 字幕对齐 → 「会说话的语义段」             │
│   A2  抽帧 → 在线视觉理解 → 本地向量化                    │
└────────────────────────────────────────────────────────┘
                         ↓
┌────────────────────────────────────────────────────────┐
│ 阶段 B：生成解说脚本                                      │
│   B1  理解文案：分段 + 结构化标签 + 向量                   │
│   B2  匹配镜头：向量粗筛 → 大模型精排 → 连贯性融合          │
│   B3  规划全局路径（可选，默认关闭）                       │
│   B4  生成脚本：分块让大模型改写成「解说句 + 起止时间」     │
└────────────────────────────────────────────────────────┘
                         ↓
              交付：project.script
```

阶段 A、阶段 B 各自有一个一键入口。**阶段 A 必须先完成**，阶段 B 才允许启动。

## 3. 启动条件

- 项目类型 = Omni、License 有效、本地 BGE 中文向量模型可用、已配置在线视觉模型（云雾 / 302 / 通义 / 豆包 / 自定义之一）。
- 阶段 A 还需要：已上传视频、已绑定字幕（或允许同时触发字幕提取）。
- 阶段 B 还需要：阶段 A 已完成、已生成并保存解说文案。

任一项不满足，系统会直接拒绝并给出明确的中文报错。

## 4. 阶段 A：生成分镜

把整段视频切成若干「会说话的语义段」，每段带：起止时间、对应字幕、画面理解（一句话简介、详细描述、动作、情绪、场景、出现的对象）、语义向量。

### 两步走

- **A1 镜头切分**：检测镜头边界 → 把字幕对齐到镜头 → 过短的段双向合并。**结果永久缓存**，只要视频和字幕没变就不再重切，即便用户选「全部重做」也只重做 A2。
- **A2 多模态特征**：抽中帧 → 默认每 8 段一批调用在线视觉模型做画面理解；批量解析失败时**自动回退逐段调用**；模型超时或命中内容安全策略时**自动降级**为「字幕 + 占位向量」继续，不会因此终止整条流水线。处理过程中会**定期落盘**，下次跑可以从断点继续。

### 三种执行方式

| 模式 | 含义 | 典型场景 |
|---|---|---|
| `auto`（默认） | 有历史结果就续跑剩余段，没有就从头跑 | 普通用户点「生成分镜」 |
| `continue` | 强制续跑，只补全未完成段 | 上次跑到一半被中断 |
| `restart` | 全部重做（A1 缓存仍复用，只重做 A2） | 换了视觉模型想重来 |

### 一键入口

如果项目还没有可用字幕，系统会**先同步提取字幕，再立刻提交分镜任务**，对用户依旧是「一次点击」。

## 5. 阶段 B：生成解说脚本

### B1 理解文案

把长文案按字数切成若干小段，调用大模型给每段打结构化标签（事件、人物、情绪、动作、场景、运镜建议、可选英文翻译），用本地 BGE 向量化（不消耗在线大模型额度）。中英文两套 prompt，**第一步选了哪种语言，整个阶段 B 都沿用**，切语言必须重跑 B1。

### B2 匹配镜头

为每一句文案找最合适的镜头候选，分三段：

1. **向量粗筛**：本地余弦相似度，每句文案取 Top 30 候选。
2. **大模型精排**：把候选连同当前句、上下句一起喂给大模型重新排序。
3. **连贯性融合**：把「向量分数 + 精排分数 + 与相邻句镜头的连续性分数」按权重加权（默认 55% 精排、30% 向量、15% 连续性）。

产物是每句的最终候选镜头列表（含分数、推荐原因、时间），**也是前端「镜头选择」面板的数据源**。

### B3 规划全局路径（默认关闭）

在 B2 候选基础上做一次全局最优路径搜索，挑出整体最连贯的镜头序列。当前默认跳过——绝大多数场景下 B2 已经够用。需要更高品质时由研发显式开启。

### B4 生成解说脚本

把整段输入按时间窗分块，并发让大模型改写成「解说句 + 起止时间」的 JSON。每批多次重试 + 后验校验，最终合并、按视频总时长校准时间，写入 `project.script`，项目状态置为 `completed`。
