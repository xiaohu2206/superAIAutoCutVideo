# 大模型并发调用清单

本文记录项目中会并发调用大模型（文本 LLM / 在线视觉模型）的入口、默认并发，以及视觉、文案两个本地模型开关开启后的行为。

## 统一配置

配置入口：

- 后端配置管理：`backend/modules/config/omni_step2_pipeline_config.py`
- 配置文件：`omni_step2_pipeline_config.json`
- 前端入口：设置页「整合模型」下的「视觉模型使用本地模型」和「文案模型使用本地模型」

核心字段：

```json
{
  "use_local_vision_model": false,
  "use_local_text_model": false,
  "local": {
    "vl_batch_size": 1,
    "infer_wall_sec": 1200,
    "vision_api_concurrency": 1,
    "text_api_concurrency": 1
  }
}
```

统一解析方法：

- `resolve_runtime_params()`：只受视觉开关控制，用于在线视觉 / Omni Step2 等视觉推理参数。
- `resolve_llm_api_concurrency(default_cloud=...)`：只受文案开关控制。关闭时返回 `default_cloud`，开启时返回 `local.text_api_concurrency`。

默认本地模式约定：

- 视觉模型 API 并发：`vision_api_concurrency=1`
- 文案模型 API 并发：`text_api_concurrency=1`
- 视觉模型单次调用超时：`1200s`
- 抽帧并发、BGE 向量化并发不随该开关降低，除非调用点另有说明。

| `backend/services/script_generation/script_builder.py` | 普通脚本单块生成、全局精修 | `script_generation/service.py` 的分段 `Semaphore`；全局精修本身是单次调用 |

## 维护约定

新增并发调用大模型时应遵循：

1. 如果是多个分块并发调用 `ai_service.send_chat()` 或 provider `chat_completion()`，使用：

```python
from modules.config.omni_step2_pipeline_config import omni_step2_pipeline_config_manager

llm_concurrency = omni_step2_pipeline_config_manager.resolve_llm_api_concurrency(default_cloud=<原云端并发>)
sem = asyncio.Semaphore(llm_concurrency)
```

2. 如果是在线视觉模型并发，使用 `resolve_runtime_params()` 中的 `api_concurrency` 与 `infer_wall_sec`。

3. 视觉调用只读视觉开关，文本 LLM 调用只读文案开关；抽帧、本地 BGE、ASR、TTS 等并发不应混入这个配置。

4. 保持关闭对应开关时原行为不变；两个开关不得互相改变对方的并发和超时。
