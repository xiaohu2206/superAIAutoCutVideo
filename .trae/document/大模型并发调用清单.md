# 大模型并发调用清单

本文记录项目中会并发调用大模型（文本 LLM / 在线视觉模型）的入口、默认并发，以及「使用本地模型」开关开启后的行为。

## 统一配置

配置入口：

- 后端配置管理：`backend/modules/config/omni_step2_pipeline_config.py`
- 配置文件：`omni_step2_pipeline_config.json`
- 前端入口：设置页「整合模型」下的「使用本地模型（Omni Step2 低并发）」

核心字段：

```json
{
  "use_local_model_pipeline": false,
  "local": {
    "vl_batch_size": 1,
    "infer_wall_sec": 1200,
    "api_concurrency": 1
  }
}
```

统一解析方法：

- `resolve_runtime_params()`：用于在线视觉 / Omni Step2 等视觉推理参数。
- `resolve_llm_api_concurrency(default_cloud=...)`：用于文本大模型并发。关闭本地模型时返回 `default_cloud`，开启本地模型时返回 `local.api_concurrency`。

默认本地模式约定：

- 大模型 API 并发：`1`
- 单次调用超时：`1200s`
- 抽帧并发、BGE 向量化并发不随该开关降低，除非调用点另有说明。

这些文件本身有 `send_chat()`，但没有独立并发池；并发由上层入口控制：

| 文件 | 调用说明 | 外层控制 |
| --- | --- | --- |
| `backend/services/script_generation/script_builder.py` | 普通脚本单块生成、全局精修 | `script_generation/service.py` 的分段 `Semaphore`；全局精修本身是单次调用 |

| `backend/services/reference_copywriting_wash/llm_client.py` | 洗稿单块 LLM 调用 | `reference_copywriting_wash/pipeline.py` 的 `Semaphore` |

## 维护约定

新增并发调用大模型时应遵循：

1. 如果是多个分块并发调用 `ai_service.send_chat()` 或 provider `chat_completion()`，使用：

```python
from modules.config.omni_step2_pipeline_config import omni_step2_pipeline_config_manager

llm_concurrency = omni_step2_pipeline_config_manager.resolve_llm_api_concurrency(default_cloud=<原云端并发>)
sem = asyncio.Semaphore(llm_concurrency)
```

2. 如果是在线视觉模型并发，使用 `resolve_runtime_params()` 中的 `api_concurrency` 与 `infer_wall_sec`。

3. 只把“会压本地大模型服务”的 API 并发纳入该开关；抽帧、本地 BGE、ASR、TTS 等并发不应混入这个配置。

4. 保持关闭开关时原行为不变；本地模式只降低大模型 API 并发和相关超时。
