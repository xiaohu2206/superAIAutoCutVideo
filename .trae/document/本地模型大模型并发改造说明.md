# 本地模型大模型并发改造说明

## 背景

项目中多处会并发调用在线视觉模型或文本大模型。云端模型可承受较高并发，但用户切换为本地部署的大模型时，过高并发容易导致显存不足、请求排队过长或本地推理服务崩溃。

本次改造将原来的统一「使用本地模型」开关拆成两个互不影响的开关：

- 「视觉模型使用本地模型」：只降低视觉模型并发、批大小，并延长视觉推理超时。
- 「文案模型使用本地模型」：只降低文案、脚本、结构化、匹配等文本 LLM 并发。

关闭任一开关时，对应模型保持原有云端参数；视觉和文案可以分别选择本地或云端。

## 配置入口

后端配置：

- `backend/modules/config/omni_step2_pipeline_config.py`
- `backend/routes/omni_step2_pipeline_routes.py`
- `backend/config/omni_step2_pipeline_config.json`

前端配置：

- `frontend/src/components/settingsPage/components/models/integrated/OmniStep2LocalPipelineSettings.tsx`
- `frontend/src/components/settingsPage/hooks/useOmniStep2PipelineConfig.ts`
- `frontend/src/services/omniStep2PipelineService.ts`

默认配置：

```json
{
  "use_local_vision_model": false,
  "use_local_text_model": false,
  "local": {
    "vl_batch_size": 1,
    "infer_wall_sec": 1200,
    "vision_api_concurrency": 1,
    "text_api_concurrency": 1
  }
}
```

说明：

- `use_local_vision_model=false`：视觉模型沿用原有云端参数。
- `use_local_text_model=false`：文本 LLM 沿用各调用点原有云端并发。
- `vl_batch_size=1`：Omni Step2 本地模型模式下单次视觉调用只处理 1 个语义段。
- `infer_wall_sec=1200`：本地视觉推理单次调用超时。
- `vision_api_concurrency=1`：本地视觉模型 API 并发上限。
- `text_api_concurrency=1`：本地文案模型及其他文本 LLM API 并发上限。

## 后端统一解析

统一方法位于 `omni_step2_pipeline_config_manager`：

- `resolve_runtime_params()`：只读取视觉开关，给在线视觉、Omni Step2 返回批大小、超时和视觉 API 并发。
- `resolve_llm_api_concurrency(default_cloud=...)`：只读取文案开关。云端模式返回原默认并发；本地文案模式返回 `local.text_api_concurrency`。
- `is_local_vision_model_enabled()` / `is_local_text_model_enabled()`：需要判断模型来源而不是解析并发时使用。

后续新增大模型并发调用时，优先使用：

```python
from modules.config.omni_step2_pipeline_config import omni_step2_pipeline_config_manager

llm_concurrency = omni_step2_pipeline_config_manager.resolve_llm_api_concurrency(
    default_cloud=<原云端并发>
)
sem = asyncio.Semaphore(llm_concurrency)
```

## 已接入的调用点

在线视觉 / 多模态：

- `backend/services/omni_multimodal_pipeline_service.py`
  - Omni Step2 在线视觉理解。
  - 云端默认：`api_concurrency=64`、`infer_wall_sec=40`。
  - 本地模式：`api_concurrency=1`、`infer_wall_sec=1200`、`vl_batch_size=1`。

- `backend/services/ai_models/vision_frame_analysis_service.py`
  - 普通镜头在线视觉分析。
  - 云端默认：`api_concurrency=64`，超时读原环境变量逻辑。
  - 本地模式：`api_concurrency=1`、`infer_wall_sec=1200`。

文案生成：

- `backend/services/script_generation/copywriting_builder.py`
  - 解说文案分段生成。
  - 云端默认并发：`3`。
  - 本地模式：`1`。

- `backend/services/reference_copywriting_wash/pipeline.py`
  - 参考稿洗稿分段生成。
  - 云端默认并发：`3`。
  - 本地模式：`1`。

脚本生成：

- `backend/services/script_generation/service.py`
  - 普通脚本分段生成。
  - 视觉脚本分段生成。
  - 云端默认并发：`5`。
  - 本地模式：`1`。

- `backend/services/script_generation/plot_analysis.py`
  - 剧情爆点分块分析。
  - 云端默认并发：`4`。
  - 本地模式：`1`。

- `backend/services/omni_generate_script_service.py`
  - Omni 解说脚本分块生成。
  - 云端默认并发：请求参数 `chunk_llm_concurrency`，默认 `32`。
  - 本地模式：`1`。

Omni 结构化与匹配：

- `backend/services/omni_copywriting_struct_embed_service.py`
  - Omni 文案结构化。
  - 云端默认并发：请求参数 `structuring_concurrency`，默认 `3`。
  - 本地模式：`1`。

- `backend/services/omni_shot_match_service.py`
  - Omni 镜头匹配 LLM 精排。
  - 云端默认并发：`32`。
  - 本地模式：`1`。

## 明确不纳入本开关的并发

这些并发不是“大模型 API 并发”，因此不随本地模型开关降低：

- 抽帧并发：例如 `vision_frame_analysis_service.py` 中的 `extract_semaphore`。
- 本地 BGE 向量化并发：例如 `omni_copywriting_struct_embed_service.py` 的 `emb_sem`、`omni_shot_match_service.py` 的 `fill_sem`。
- ASR 并发：`fun_asr_service.py`。
- TTS 并发：`tts_service.py`、`qwen_online_tts_service.py`、`omni_script_tts_service.py`。

## 前端行为

设置页「整合模型」显示两个独立的本地模型卡片：

- 两个开关默认都关闭，可独立勾选。
- 视觉卡片显示：`vl_batch_size`、`infer_wall_sec`、`vision_api_concurrency`。
- 文案卡片显示：`text_api_concurrency`。
- 参数自动保存到独立 JSON 配置。
- 关闭某一开关只恢复该模型类型的云端策略，不影响另一类模型。

## 旧配置迁移

加载旧 JSON 时自动执行以下迁移并回写新格式：

- `use_local_model_pipeline` 同时迁移到 `use_local_vision_model` 和 `use_local_text_model`。
- `local.api_concurrency` 同时迁移到 `vision_api_concurrency` 和 `text_api_concurrency`。
- API 暂时继续接受旧字段，便于旧前端平滑升级；新响应与新保存文件只使用拆分后的字段。
